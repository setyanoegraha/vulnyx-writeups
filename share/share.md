# share

## Executive Summary

| Machine | Author | Category | Platform |
| :--- | :--- | :--- | :--- |
| share | d4t4s3c | Low | VulNyx |

**Summary:** The share machine exposed three services: SSH, a stock Apache default page, and a **Weborf** WebDAV server on port 8080 running an old, vulnerable version. Weborf 0.12.2 was vulnerable to a path traversal flaw that allowed reading arbitrary files outside the web root via URL-encoded dot-dot traversal. The `/etc/passwd` file was pulled first, revealing a single non-system user, `tim`. The traversal was then pointed at `~tim/.ssh/id_rsa`, silently exfiltrating `tim`'s encrypted SSH private key. The key's passphrase was no match for `ssh2john` and a John the Ripper run against the rockyou wordlist, which recovered it in under a second: `ilovetim`. Logging in over SSH as `tim` with the key and passphrase produced a foothold on the box. Sudo privileges revealed `tim` could run `/usr/bin/yafc` (a FTP client) as root without a password, and yafc's interactive shell exposes a `!` escape to run arbitrary shell commands. Invoking `sudo -u root /usr/bin/yafc` and entering `!/bin/bash` spawned a root shell, and both flags were read.

## Privilege Escalation

### The yafc Shell Escape

6. Checking `sudo` privileges for `tim` exposed the root escalation path:

```bash
tim@share:~$ sudo -l
Matching Defaults entries for tim on share:
    env_reset, mail_badpass, secure_path=/usr/local/sbin\:/usr/local/bin\:/usr/sbin\:/usr/bin\:/sbin\:/bin

User tim may run the following commands on share:
    (root) NOPASSWD: /usr/bin/yafc
```

`tim` could run `/usr/bin/yafc`, a command line FTP client, as root without a password. Like many interactive utilities, yafc offers a shell escape: any command prefixed with `!` runs locally through `/bin/sh`, which as the sudo'd root process means a root shell.

7. The FTP client was launched as root, and the escape was used to spawn a shell:

```bash
tim@share:~$ sudo -u root /usr/bin/yafc
yafc 1.3.7
This program comes with ABSOLUTELY NO WARRANTY; for details type 'warranty'.
This is free software; type 'copyright' for details.

yafc> !/bin/bash
root@share:/home/tim# su -
root@share:~# id;whoami;hostname
uid=0(root) gid=0(root) grupos=0(root)
root
share
```

8. Both flags were read from the root shell:

```bash
root@share:~# cat /home/tim/user.txt /root/root.txt 
```

The shell escape from the misconfigured `yafc` sudo rule produced a root shell, and the user and root flags were recovered to complete the compromise.

## Attack Chain Summary

1. **Reconnaissance**: A ping sweep isolated the target at `192.168.56.118`, and Nmap exposed SSH on port 22, Apache on port 80, and a Weborf WebDAV server on port 8080 whose root listing exposed system directories.

2. **Vulnerability Discovery**: Weborf 0.12.2 was vulnerable to a path traversal flaw exploitable with URL-encoded `..%2f` sequences, allowing arbitrary file reads. `/etc/passwd` revealed the user `tim`.

3. **Exploitation**: The traversal was used to download `tim`'s encrypted SSH private key from `~/.ssh/id_rsa`. `ssh2john` converted the key, and John the Ripper cracked the passphrase `ilovetim` from rockyou in under a second, granting SSH access as `tim`.

4. **Internal Enumeration**: A `sudo` rule allowed `tim` to run `/usr/bin/yafc` as root without a password.

5. **Privilege Escalation**: yafc's interactive shell supports the `!` shell-escape command. Launching `sudo -u root /usr/bin/yafc` and entering `!/bin/bash` spawned a root shell, allowing both flags to be read.
